OPFS vs IndexedDB: a benchmark you can run yourself

For heavy lifting in the browser, such as offline data, large datasets or files, you have two real options: IndexedDB and the Origin Private File System (OPFS). Most published benchmarks come from vendors. This one runs in your browser, on your device, right on this page.

Practical rules

  • Batch writes into one transaction. Many tiny transactions are the most common IndexedDB slowdown.
  • Split big data into chunks instead of one giant record, so updates only rewrite what changed.
  • Prefer ArrayBuffers for binary data in IndexedDB. Blob storage has had browser-specific problems, notably on older Safari versions.
  • Ask for persistence with navigator.storage.persist() when losing the data would hurt.
  • Test in every target browser. Storage performance differs more between browsers than almost anything else.

FAQ

Is OPFS faster than IndexedDB?

Often, for large binary or file-like data, especially through a Web Worker with a synchronous access handle. But results vary a lot by browser, device and access pattern. Run the benchmark on this page in the browsers your users actually use.

When should I use IndexedDB instead of OPFS?

Use IndexedDB for structured records you need to look up, filter or index, such as offline app data, caches and queues. Use OPFS for files and large binary blobs you read and write as a whole or in chunks, like media, exports, or a WebAssembly database file.

Do OPFS and IndexedDB work in Web Workers?

Yes. Both are available in workers, which is where heavy work belongs so the UI stays responsive. OPFS's fastest API, createSyncAccessHandle, is only available inside dedicated Web Workers.

How much can I store in IndexedDB or OPFS?

Both share the same per-origin quota, which depends on the browser and free disk space and is usually far larger than localStorage. Check the current estimate with navigator.storage.estimate(), and request persistence with navigator.storage.persist() if the data shouldn't be evicted.

Does this benchmark send my data anywhere?

No. It generates dummy data, writes and reads it locally in your browser, then deletes it. Nothing leaves your device.
