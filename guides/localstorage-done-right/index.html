localStorage done right: a safe 30-line wrapper

localStorage is perfect for small things: a theme, a dismissed banner, a draft. It's also easy to misuse. Here's a tiny, dependency-free wrapper that adds expiration, versioning, quota handling and cross-tab sync, and the point where you should move to IndexedDB instead.

By Alexandru Cobuz · Senior full-stack engineer · 6 min read

When localStorage is the right tool

  • Small, non-sensitive values: theme, language, layout preferences, dismissed notices.
  • Read once at startup and written occasionally.
  • Simple data that's easy to serialise as JSON.

If you're storing lists of records, files, or anything you'd want to query, skip ahead to IndexedDB and OPFS.

When to move to IndexedDB

  • You're storing more than a few hundred kilobytes, or a growing list of records.
  • You need to query or filter data, not just read one key.
  • You store files, images or binary data.
  • You want to do the work in a Web Worker, where localStorage isn't available.

That's where IndexedDB and OPFS come in. Compare them with a benchmark you can run in your browser.

FAQ

How much data can localStorage store?

Around 5 MB per origin in most browsers, stored as UTF-16 strings, so the practical limit for your data is often lower. When you go over, setItem throws a QuotaExceededError, which is why every write should be wrapped in try/catch.

Does localStorage expire?

No. Data stays until your code or the user clears it. To expire values, store a timestamp next to the data and check it on read, as the wrapper in this guide does. Use sessionStorage if data should only live as long as the tab.

Is localStorage slow or blocking?

It's synchronous, so every read and write runs on the main thread. For small values that's negligible. It becomes a problem with large values or frequent writes, such as saving on every keystroke or render. Debounce writes, and move large or structured data to IndexedDB.

Is it safe to store tokens in localStorage?

Avoid it for sensitive tokens. Any script running on your page, including injected ones in an XSS attack, can read localStorage. Prefer HttpOnly, Secure cookies for session tokens, and keep localStorage for non-sensitive preferences.

How do I sync localStorage between tabs?

Listen for the storage event on window. It fires in every other tab of the same origin when a value changes, not in the tab that made the change, so each tab can update its UI when another tab writes.
