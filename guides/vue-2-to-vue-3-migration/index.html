Vue 2 is end of life: how to upgrade to Vue 3

Vue 2 reached end of life on 31 December 2023. It still runs, but it no longer gets security or browser fixes, and the libraries around it are moving on. Here's how to upgrade a live Vue 2 app to Vue 3 step by step, without stopping feature work for months.

By Alexandru Cobuz · Senior full-stack engineer · 10 min read

The short answer

  • Vue 2 is already end of life. The final version is 2.7.16, released in December 2023.
  • You don't need a rewrite. Vue 3 still supports the Options API, so most components only need small changes.
  • Use the migration build. @vue/compat is Vue 3 that behaves like Vue 2 and warns you about everything that has to change.
  • The libraries are usually the hard part, especially UI frameworks such as Vuetify 2, BootstrapVue and Element UI.
  • On big apps, expect surprises. In my case, the user session broke after the migration, and I rebuilt it on Pinia.

Why upgrade now

The official Vue 2 LTS page says that after end of life Vue 2 gets no more updates, “including security and browser compatibility fixes”. Your app won't stop working tomorrow, but every month adds risk:

  • Security: a vulnerability found in Vue 2 or its compiler won't be fixed. Security audits and customer questionnaires increasingly ask about end-of-life software.
  • Libraries: new versions of routers, UI kits, charts and editors target Vue 3. You end up pinned to old versions, with their own unfixed bugs.
  • Tooling: Vue CLI is in maintenance mode, and current build tools and test runners are built for Vue 3.
  • Hiring: developers who join now learn Vue 3, and older patterns slow them down.

If you truly can't upgrade yet, paid extended support exists: the LTS page points to HeroDevs. It buys time, but it isn't a plan.

The upgrade path

This follows the order of the official migration build guide, grouped into four stages. The app stays deployable after each one.

Step 1: get ready on Vue 2.7

Vue 2.7 backported the Composition API and <script setup>. Upgrading to it first is a small change that lets new code use the Vue 3 style while the old code still runs:

  • Upgrade to vue@2.7 and remove @vue/composition-api if you used it.
  • Move old slot syntax (slot, slot-scope) to v-slot.
  • Replace event buses, filters and $children now. All three are removed in Vue 3, and the fixes work in Vue 2 too.
  • If you still use Vue CLI and Webpack, move to Vite now. It's often the biggest win of the whole migration, as the next section shows.

Webpack to Vite: the biggest win on big repos

If your app still builds with Vue CLI and Webpack, moving to Vite is often the change your team notices most. On a large repository I worked on, the build pipeline went from about 3 minutes to under 20 seconds. Every push, every pull request and every deploy got faster, which adds up to hours each week across a team.

The bigger the repository, the bigger the gain:

  • Development: Webpack bundles the whole app before the dev server starts. Vite serves your source files to the browser as native ES modules and only transforms the files a page actually requests, so start-up stays fast as the app grows.
  • Hot reload: a change replaces one module instead of rebuilding a bundle, so saving a file shows up almost instantly.
  • Production builds: current Vite builds with Rolldown and processes CSS with Lightning CSS, both written in Rust, instead of a long chain of JavaScript loaders.

From my experience: big apps don't migrate smoothly

On a small app, the steps above can go quickly. On a large one, don't expect a smooth transition. I migrated a large monolith, and the hardest problems weren't in the components at all.

The user session was kept by a Vue 2 store library, and it broke after the migration. The console showed no warning about it, because the migration build only covers Vue itself, not the libraries around it. I rebuilt the session state on Pinia, and it has been stable since.

  • Find everything that keeps state between pages before you start: sessions, login, carts, saved filters, and any plugin that stores data in localStorage or cookies.
  • Test log in, refresh and log out by hand after every step, not only at the end.
  • Plan time for the surprises. In a monolith, a small change in one place can break a screen nobody thought was related.

Step 4: remove the migration build

When the console is quiet and no dependency still needs Vue 2 behaviour, switch components to Vue 3 mode one at a time, then all at once:

Finally, remove the vue alias, the compatConfig option and @vue/compat itself. The migration build is allowed in production, with a small cost in size and speed, so you don't have to finish everything before your next release.

Tests: your safety net

  • Write a few end-to-end tests first for login, checkout or whatever earns money. They don't care which Vue version runs underneath.
  • Upgrade @vue/test-utils to v2. propsData becomes props, and mocks, stubs and plugins move under global.
  • Treat console warnings as test failures in CI once a feature ID is fixed, so it can't come back.
  • Release in small steps and watch error tracking after each one.

What doesn't migrate

  • Internet Explorer 11: Vue 3 doesn't support it. If you must support IE11, you have to stay on Vue 2.
  • Code that relies on Vue 2 internals, such as private VNode properties. Some old plugins do this and need replacing.
  • Nuxt 2: it reached end of life in June 2024 and has its own path to current Nuxt. Plan it as a separate project.
  • Server rendering with vue-server-renderer moves to @vue/server-renderer and a different setup.

FAQ

When did Vue 2 reach end of life?

On 31 December 2023. The final release is Vue 2.7.16, and Vue 2 no longer receives updates, including security and browser compatibility fixes.

Is it safe to keep running Vue 2?

The app keeps working, but new vulnerabilities in Vue 2 won't be fixed and libraries are dropping support. Paid extended support exists, but upgrading to Vue 3 is the long-term solution.

Can I upgrade from Vue 2 to Vue 3 gradually?

Yes. The migration build, @vue/compat, runs your app on Vue 3 with Vue 2 behaviour and warns about each change, so you can fix them in small releases. It can run in production while you finish.

Do I have to rewrite my components with the Composition API?

No. Vue 3 still supports the Options API. Most components need only small changes, such as renamed lifecycle hooks and the new v-model.

How long does a Vue 2 to Vue 3 migration take?

It depends mostly on your libraries and on how much code uses removed features. Count those patterns first; a UI framework without a Vue 3 version usually takes longer than Vue itself.

Is Vite faster than Webpack for Vue apps?

Usually much faster, and the gap grows with the size of the app. On a large Vue repository, my build pipeline went from about 3 minutes with Webpack to under 20 seconds with Vite.
